\chapter{Background}
\label{chap:background}

Learning-based security analysis converts observations into representations and evaluates a
fitted decision rule on a stated population. Its interpretation depends on the evidence
available to the analyser and on the experimental protocol \cite{arp2022dos}. This chapter
defines the foundations shared by the contribution chapters. Android applications and program
representations appear first because they support the dissertation's main studies.
Section~\ref{sec:background:networks} supplies the network and process foundations for
Chapter~\ref{chap:anomaly}. Comparisons with specific competing systems remain in the
contribution chapters.

\section{Android Applications and Their Analysis}
\label{sec:background:android}

\subsection{Android Malware Detection}
\label{sec:background:android:detection}

Malware detection assigns a software artefact to a benign or malicious class. Multiclass
malware analysis uses a finer label scheme: a corpus may group malicious applications by
family or define broader application categories \cite{bilot2024survey}. Each target partitions
the applications differently, so its metrics answer a different question. In this dissertation,
\hybroid{} evaluates binary detection and
five-class category classification, with Benign as one category. \hgann{} evaluates binary
detection and malware-family classification on Drebin, together with category classification
on CICMalDroid \cite{norouzian2021hybroid,norouzian2025hgannmal}.

Signature and heuristic detectors search for specified indicators of malicious activity.
Learning-based detectors acquire observable properties of an application, encode them as a
numerical or relational representation. They then fit a decision rule to labelled samples
\cite{arp2014drebin,liu2023deeplearning}. DREBIN, for example, extracts manifest and bytecode
features from an Android package and embeds them in a joint vector space. A linear classifier
operates on that representation \cite{arp2014drebin}. Graph-based systems add a structural
encoding before classification \cite{bilot2024survey}. The prediction concerns an application
even when the representation is assembled from instructions, methods or recorded network
flows.

The evidence available to a detector remains bounded by its acquisition process. Static
analysis depends on the code recovered from the package and on the analyser's approximations;
dynamic analysis depends on the paths exercised during observation. Obfuscation and loading at
runtime can conceal relevant behaviour, while changes in applications and attack techniques can
weaken associations learned from historical data \cite{liu2023deeplearning}. The following
subsections develop these observation limits. Section~\ref{sec:background:evaluation:bias}
addresses temporal change, related samples and other protocol choices that affect reported
performance.

\subsection{Dalvik Bytecode, Manifest, and Permissions}
\label{sec:background:android:artefacts}

An APK is an installation archive containing compiled code and application resources
\cite{aosp2026appfundamentals}. Java and Kotlin compilation produces Dalvik Executable (DEX)
files. These are packaged as \texttt{classes.dex} and, for multidex applications, additional
numbered files \cite{aosp2026dexformat}. Android Runtime (ART) executes the DEX bytecode format also
used by its predecessor, Dalvik \cite{aosp2026art}. Instructions contain an opcode and
operand fields, which may identify registers or constants and refer to methods or strings
\cite{aosp2026dalvikbytecode}. The opcode embedding in Section~\ref{sec:hybroid:5} omits
these operands; call-graph extraction can still use their method references.

Android normally isolates applications through separate Linux user identities and processes
\cite{aosp2026appfundamentals}. Within an application, activities provide user interfaces and
services support work without an activity interface. Broadcast receivers respond to events,
while content providers expose data through controlled interfaces. These components have
distinct lifecycles, with callbacks invoked by the framework. Static analysis must model those
entry points and callback relations to recover the corresponding behaviour
\cite{arzt2014flowdroid}.

The manifest declares application components and requested permissions, together with intent
filters and device requirements. Its metadata can be parsed without reconstructing control
flow. DREBIN obtains four of its eight feature groups from the manifest and the remainder from
disassembled bytecode \cite{arp2014drebin}.

Permissions mediate access to protected data and operations. A request in the manifest records
a declared requirement; the actual grant depends on the permission and the platform.
In the current runtime-permission model, \emph{dangerous} permissions require a grant before
protected functionality can be used. \emph{Signature} permissions instead depend on the application's
signing relationship to the permission's defining application or operating system, and can
protect privileged operations \cite{felt2011android,aosp2026permissions}. Selecting dangerous
permissions therefore selects one class of protected capabilities.

Permission-to-API mappings also depend on platform version. PScout recovered these mappings
from framework source across Android 2.2 to 4.0 and documented gaps in the available API
specification \cite{au2012pscout}. More recent work examines permission deprecation as a
source of change in permission-based detection \cite{sabbah2026understanding}. These findings
motivate explicit platform assumptions when sensitive APIs are selected, as in
Section~\ref{sec:hgann:5}.

\subsection{Static, Dynamic, and Hybrid Analysis}
\label{sec:background:android:analysis}

Static analysis examines an application without executing it. It can inspect code outside the
paths exercised by a test harness, subject to the code available and the analyser's
approximations. Static methods accounted for 73 per cent of the deep-learning studies reviewed
by Liu et al.\ for 2014--2021 \cite{liu2023deeplearning}.
Figure~\ref{fig:background:apk} distinguishes package artefacts from execution observations.

  \centering

  \caption[Android package contents and analysis modes]{Package artefacts and analysis modes.
  Static analysis reads available code and metadata and infers possible behaviour.
  Dynamic analysis records behaviour along the execution paths exercised by the harness;
  network traffic from those executions supplies the additional observation used in
  Chapter~\ref{chap:hybroid}.}
  \label{fig:background:apk}
\end{figure}

Standard toolkits provide disassembly and call-graph construction
\cite{desnos2012android,valleerai2010soot}; FlowDroid adds lifecycle-aware taint analysis
\cite{arzt2014flowdroid}. An analysis restricted to recovered DEX code can omit native
functionality or runtime-loaded code. More precise reasoning also has computational limits:
Moser et al.\ construct x86 obfuscations whose opaque constants encode instances of the
NP-hard 3SAT problem \cite{moser2007limits}.

Dynamic analysis observes an execution through instrumentation. Examples include on-device
taint tracking \cite{enck2014taintdroid} and emulation that reconstructs operating-system and
Dalvik-level events \cite{yan2012droidscope}. Recorded traffic supplies a further observation
channel. Coverage is limited to the paths triggered during the observation period, and
applications may recognise an analysis environment and alter their behaviour
\cite{petsas2014rage,vidas2014evading}.

Hybrid analysis combines static and dynamic observations. Within-system studies have reported
benefits from their combination, with outcomes dependent on the observation types and the
stimulation used during execution \cite{lindorfer2015marvin,onwuzurike2018family}.
Feature-level fusion supplies the derived features together to a classifier, so both
observations must first be summarised for the same unit, such as an application. Its additional
value is assessed against each modality alone for the same application cohort and prediction
task, as in Chapter~\ref{chap:hybroid}.

\subsection{Obfuscation, Packing, and Repackaging}
\label{sec:background:android:obfuscation}

Obfuscation transforms code to impede analysis while aiming to preserve its functionality.
Legitimate developers use it to protect software: Wermke et al.\ found developer-applied
obfuscation in 24.92 per cent of 1.7 million free Google Play applications
\cite{wermke2018large}. Its use differs across application sources and techniques
\cite{dong2018understanding}. Hammad et al.\ evaluated 29 obfuscation strategies and documented
losses in commercial anti-malware detection \cite{hammad2018large}. A later evaluation of
twelve learning-based detectors also found performance losses under obfuscation, temporal
change and adversarial perturbations \cite{gao2024comprehensive}.

Packing conceals a payload behind a loader that recovers it during execution. The loader and
metadata may remain accessible to static analysis while the original payload requires
unpacking. Commercial and custom Android packers use different mechanisms, which limits the
coverage of individual unpacking tools \cite{duan2018things}.

Repackaging reuses an application with modifications; malicious piggybacking inserts additional
code into a benign carrier \cite{li2017understanding}. Such reuse creates code-related
samples whose placement across training and test partitions requires attention.
Section~\ref{sec:background:evaluation:bias} addresses the resulting evaluation bias.

\section{Graph Representations of Programs}
\label{sec:background:graphs}

A program representation specifies both the entities modelled and the relations between them.
The Android chapters use basic blocks and methods at different stages; their graph edges
therefore have different meanings.

\subsection{Control-Flow and Function-Call Graphs}
\label{sec:background:graphs:pairwise}

The intra-procedural \emph{control-flow graph} (CFG) used here is a directed graph over the
basic blocks of one method. A basic block is a maximal instruction sequence with one entry
and no branch except possibly at its end. An edge records a possible transfer of control
between blocks \cite{bilot2024survey}. A \emph{call graph} instead has procedures as vertices,
with an edge from $f$ to $g$ when a call site in $f$ may invoke $g$. For Android, this
dissertation uses \emph{function-call graph} (FCG) for the method-level object recovered from
bytecode \cite{gascon2013structural,norouzian2025hgannmal}.

A sound call-graph analysis over-approximates possible calls under its execution model.
Practical recovery can introduce infeasible edges and omit unresolved targets, for example
through reflection or incompletely modelled callbacks \cite{arzt2014flowdroid}.
The recovered graph thus expresses the analyser's approximation of program structure.
Its coverage depends on the toolkit and execution assumptions
\cite{desnos2012android,valleerai2010soot}.

CFG embeddings can serve as vertex features in an FCG, so that block-level information and
inter-method calls contribute to one representation \cite{bilot2024survey}. Pooling a set of
independently embedded CFGs supplies method information without call edges. These constructions
must be distinguished when an application vector is described. Other feature choices include
abstraction of APIs to packages or families \cite{onwuzurike2019mamadroid}, learned CFG
features \cite{dai2016discriminative,xu2017neural}, and embeddings of a method's syntax
\cite{alon2019code2vec}.

\paragraph{Program dependence and slicing.} Data dependence relates a value's definition to
uses that it can affect. Control dependence relates execution of a statement to the outcome
of a predicate. A program dependence graph represents these relations explicitly.
A backward slice identifies statements and predicates that may affect selected values at a
specified program point. Interprocedural slicing follows dependencies across procedure
boundaries and must account for calling context \cite{horwitz1990interprocedural}.
A call-graph neighbourhood alone does not supply these data and control dependencies.
Section~\ref{sec:hgann:5} uses slicing around sensitive API call sites; the definition here
does not establish the scope or precision of that implementation.

\subsection{Hypergraphs and Higher-Order Relations}
\label{sec:background:graphs:hypergraphs}

An undirected hypergraph $\mathcal{H} = (\mathcal{V}, \mathcal{E}, w)$ has a finite vertex set
$\mathcal{V}$ and a family $\mathcal{E}$ of nonempty subsets of $\mathcal{V}$. Each hyperedge
$e$ carries a weight $w(e)>0$. The incidence matrix
$H\in\{0,1\}^{|\mathcal{V}|\times|\mathcal{E}|}$ has entry $h(v,e)=1$ exactly when $v\in e$.

The vertex degree and hyperedge degree are
\[
  d(v)=\sum_{e\in\mathcal{E}}w(e)h(v,e),
  \qquad
  \delta(e)=\sum_{v\in\mathcal{V}}h(v,e)=|e|.
\]
The diagonal matrices $D_v$, $D_e$ and $W$
contain vertex degrees, hyperedge degrees and hyperedge weights, respectively
\cite{zhou2006learning}. An undirected simple graph is the special case in which
$\delta(e)=2$. A hyperedge records group membership; it does not by itself encode call
direction or execution order.

\emph{Clique expansion} replaces each hyperedge by pairwise edges between its members.
An unweighted projection cannot distinguish one hyperedge on three vertices from three
separate pairwise relations on those vertices. \emph{Star expansion} introduces one vertex
per hyperedge and links it to the member vertices \cite{agarwal2006higherorder}. If the two
vertex types and their incidence links are retained, this bipartite representation preserves
the hyperedge memberships. Figure~\ref{fig:background:hypergraph} illustrates the loss in the
unweighted clique projection.

Retaining a hypergraph and exploiting its group structure are separate properties. Agarwal
et al.\ reduce several spectral learning formulations to graph-expansion operators
\cite{agarwal2006higherorder}. For the random walks studied by Chitra and Raphael,
\emph{edge-independent} vertex weights give a transition matrix that can be realised on a
weighted clique expansion. They also exhibit \emph{edge-dependent} cases for which this
equivalence fails \cite{chitra2019randomwalks}. These results concern the specified walks;
other operators require their own analysis.

Wang and Kleinberg characterise ambiguities in reconstructing hypergraphs from unweighted
clique projections \cite{wang2024graphs}. Kang et al.\ evaluate expansion methods through
learned embeddings and hypergraph reconstruction, with downstream comparisons
\cite{kang2024low}; those experiments assess the expansion-and-learning procedure together.
A recent preprint organises hypergraph architectures by the patterns they can represent
\cite{jiang2026widthwall}. For program analysis, constructing hyperedges from an FCG adds a
chosen grouping of recovered methods. Its value for classification remains an empirical
question, distinct from the information retained by the representation.

\section{Learning over Graphs}
\label{sec:background:learning}

Graph learning assigns trainable operations to the structures defined above. The distinction
between vertex-level computation and application-level prediction is important for both
Android studies.

\subsection{Message Passing}
\label{sec:background:learning:messagepassing}

In a message-passing network, each vertex has a state that is updated from neighbouring
states over a fixed number of rounds. Aggregation is invariant to the order in which
neighbours are presented \cite{gilmer2017neural}. In the GCN formulation of Kipf and Welling,
graph degrees determine the normalised neighbour coefficients, while feature transformations
remain trainable \cite{kipf2017semi}.

A graph-level \emph{readout} combines the final vertex states into a fixed-width representation.
Sums or means are simple examples; learned invariant readouts are also possible
\cite{gilmer2017neural,xu2019powerful}. Reordering vertices should reorder vertex outputs
without changing the graph-level prediction. Shared local operations and an invariant
readout allow graphs of different sizes to be processed by the same model. In the Android
chapters, the final prediction concerns an application, even when the intermediate learning
operates on blocks or methods.

For standard neighbourhood-aggregation networks with corresponding initial node features,
graph discrimination is bounded by one-dimensional Weisfeiler--Leman colour refinement.
This procedure repeatedly refines a vertex's label from its current label and the multiset
of neighbouring labels. Injective aggregation and readout can attain that bound
\cite{xu2019powerful}. Depth introduces a separate concern: repeated normalised propagation
can reduce distinctions between vertex representations, the effect termed
\emph{oversmoothing} \cite{li2018deeper}.

\subsection{Attention}
\label{sec:background:learning:attention}

Graph attention learns scores for available vertex--neighbour pairs and normalises them
within each neighbourhood to weight the messages \cite{velickovic2018graph}.
Content-dependent weighting is also used in sequence attention \cite{vaswani2017attention}.
The scoring function determines which relative weightings the model can express.

The original GAT's additive score has a static-ranking restriction: query vertices rank
their shared candidate neighbours in the same order. GATv2 changes the scoring function to
permit query-dependent rankings \cite{brody2022gatv2}. The restriction concerns ordering,
not equality of the numerical coefficients. Section~\ref{sec:hgann:8} applies the same
argument to the additive hyperedge score used by \hgann{}.

Fang et al.\ analyse scoring capacity under explicit parameter and architecture assumptions
and evaluate models on pairwise graph tasks. Their reported means show GAT above the
non-attentive baselines on some node-classification datasets and below them on others
\cite[Table~2]{fang2025kaa}. This supports task-dependent evaluation, rather than a universal
ranking of attentive and non-attentive models. The findings do not establish the behaviour
of attention over Android hypergraphs.

\subsection{Hypergraph Convolution}
\label{sec:background:learning:hypergraphconvolution}

Hypergraph convolution aggregates vertex states within hyperedges and returns the resulting
messages to their member vertices. HGNN and HGNN+ specify such propagation through the
incidence structure and degree normalisation \cite{feng2019hypergraph,gao2023hgnn}.
Other designs approximate hyperedges by graph edges \cite{yadati2019hypergcn} or learn
multiset aggregation functions \cite{chien2022allset}. Equivariant networks and higher-order
Transformers provide further approaches to permutation-aware hypergraph learning
\cite{kim2022equivariant,kim2021transformers}.

Hypergraph attention assigns learned real-valued weights to incidences
\cite{bai2021hypergraphattention}. In the \hgann{} operator, this changes the strength of
existing memberships while their support remains fixed. Learning those weights therefore
differs from changing which methods belong to a hyperedge. Earlier Android hypergraph work
used call-neighbour and permission-based groups with non-attentive operators
\cite{zhang2023android}.

Averaging within hyperedges favours smooth signals. Li et al.\ analyse the role of
high-frequency components in hypergraph learning \cite{li2026highpass}, while HGNNv2
introduces a stability-oriented design based on anisotropic diffusion
\cite{gao2026hgnnv2}. These developments address particular properties of propagation.
To attribute an empirical difference to attention, its learned weights must be compared
with a fixed-weight alternative on the same hyperedges, with a common normalisation
convention. Chapter~\ref{chap:hgann} separates its operator analysis from the comparisons
of complete configurations.

\section{Detection in Networked and Cyber-Physical Systems}
\label{sec:background:networks}

Network and industrial detectors operate on several observation units. Traffic can be
represented by flow records or service interactions; a process detector instead receives
measurements of the physical system. Chapter~\ref{chap:anomaly} evaluates network records and
process measurements, with service interactions retained as an exploratory example.

\subsection{Anomaly Detection as a Security Task}
\label{sec:background:networks:families}

Signature-based detection matches specified attack patterns, whereas anomaly detection
identifies deviations from a reference model of expected behaviour
\cite{paxson1999bro,chandola2009anomaly}. An anomaly detector may return a binary label or an
anomaly score. A threshold converts the score into a decision and therefore determines which
deviations are reported \cite{chandola2009anomaly}.

The unit and context of the decision define what constitutes a deviation. A point anomaly is
unusual as an individual observation. A contextual anomaly is unusual under a particular
condition, such as an operating state, while a collective anomaly arises from a related group
whose individual elements need not be unusual \cite{chandola2009anomaly}. These distinctions
matter for the studies in Chapter~\ref{chap:anomaly}: the SWaT method derives timestamp decisions from
multivariate windows (Section~\ref{sec:anomaly:gan}), and the exploratory service-graph method evaluates a
relation against learned communication structure
(Section~\ref{sec:anomaly:service-graphs}).

An unusual observation can reflect legitimate activity, so an anomaly score requires a security
interpretation \cite{sommer2010outside}. Learning regimes also depend on the available labels.
Supervised classification uses labelled examples of the target classes. Normal-only training
estimates a reference from observations assumed benign, while unsupervised methods work with
unlabelled data under assumptions about its composition \cite{chandola2009anomaly}. Labels used
for feature selection or threshold choice make the development procedure partly supervised even
when the model's fitting objective uses no class labels.

Local-density methods compare a point with its neighbourhood \cite{breunig2000lof}, and
isolation methods exploit the short partition paths of isolated observations
\cite{liu2008isolation}. Reconstruction methods encode observations and attempt to reproduce
them; reconstruction discrepancies provide scores relative to the fitted representation
\cite{ruff2021unifying,pang2021deep}. Relational methods can assess vertex attributes
together with graph structure \cite{akoglu2015graph}. Each method must specify its normality
reference and the unit it scores.

\subsection{Network Flows as a Unit of Observation}
\label{sec:background:networks:flows}

A conventional IP flow groups packets by source and destination addresses and ports, together
with the transport protocol. Exporters summarise the traffic through quantities such as
duration, packet counts and byte totals; direction and timeout rules determine the exported
records \cite{sperotto2010overview}. Payload-independent features remain available when
application payloads are encrypted, provided the corresponding headers can be observed.
Their distribution can still change with protocols or execution conditions.

Flow records are an observation choice, not a universal unit of network behaviour. Service
messages and layer-2 industrial traffic require other identifiers.
Section~\ref{sec:hybroid:7} defines how \hybroid{} aggregates bidirectional flow records into
an application-level vector. Section~\ref{sec:anomaly:iuno-corpus} defines the windowed industrial
connection records used by \nadics{}; Section~\ref{sec:anomaly:service-graphs} illustrates
service relations in the exploratory IoT study.

\subsection{Communication Structure in Industrial and IoT Networks}
\label{sec:background:networks:industrial}

Industrial communications often repeat under a fixed operating mode. Barbosa et al.\ exploit
this regularity through SCADA flow whitelists, while also observing false alarms from rare
legitimate activity \cite{barbosa2013flow}. Yoon and Ciocarlie model communication patterns
between host pairs \cite{yoon2014communication}. Traffic graphs also describe host
interactions \cite{iliofotou2007network,jin2009unveiling}, and enterprise-network studies
infer service dependencies from passive observations
\cite{bahl2007towards,chen2008automating,natarajan2012nsdminer}.

Cyber-physical detection can use sensor and actuator series to assess the controlled process
\cite{mathur2016swat,kravchik2018detecting,goh2016swatdataset}. These observations differ
from the packets that transport them. In a related task, Maali et al.\ evaluate IoT
\emph{device identification} across operating modes, collection periods and sites
\cite{maali2025evaluating}. Their transfer results concern device identification;
they motivate examining changing observation conditions without supplying a detection rate
for industrial anomalies.

\subsection{Datasets and Measurement Limits}
\label{sec:background:networks:datasets}

Dataset construction can introduce predictive associations unrelated to the intended threat.
KDD~99 contains redundant records \cite{tavallaee2009nslkdd}; later audits identify
construction artefacts in CICIDS2017, UNSW-NB15 and other intrusion datasets
\cite{flood2024bad}. Kus et al.\ distinguish detection of attack types represented during
training from performance on types absent from training \cite{kus2022false}.

Wolsing et al.\ review 70 publications and evaluate four deliberately simple industrial
detectors against selected comparators on industrial datasets. Their results show that
simple process-value tests can be competitive with more complex methods
\cite{wolsing2022simple}. The comparison supports including appropriate simple baselines
under a stated protocol. The general evaluation criteria are developed in
Section~\ref{sec:background:evaluation:bias}.

\section{Adversarial Machine Learning}
\label{sec:background:adversarial}

Adversarial machine learning studies attackers who choose changes to training data or inference
inputs with the aim of altering model behaviour, together with methods for resisting those
changes \cite{biggio2018wildpatterns}. Such strategic manipulation differs from incidental noise
or distributional change because the attacker selects the modification to serve an objective. A
robustness statement is therefore conditional on the attack goal, the attacker's knowledge and
the permitted transformations
\cite{carlini2019evaluating}. Adversarial evaluation tests a learning system under those
conditions.

\paragraph{Threat models.} A threat model states the attacker's goal and knowledge, together
with the capabilities and constraints governing permitted modifications
\cite{biggio2014security,vassilev2025adversarial}. White-box evaluation gives access to the
model's architecture and parameters; a perfect-knowledge formulation can also include the
training data \cite{biggio2018wildpatterns}. Black-box attacks can use prediction queries
or transfer examples from a substitute model, with the available interface stated explicitly
\cite{papernot2017practical,kurakin2018competition}. Grey-box access denotes partial
knowledge. In the grey-box evasion setting of Chapter~\ref{chap:advml}, training is fixed;
this capability constraint is distinct from knowledge of the training data.
A survey of 271 practitioners documents mismatches between academic access assumptions and
deployment conditions \cite{grosse2024towards}.

\paragraph{Classes of attack.} Evasion modifies test-time inputs to change a trained model's
decisions \cite{biggio2013evasion}. Poisoning intervenes in training data or the learning
process \cite{biggio2012poisoning,jagielski2018manipulating}. Training-time backdoor attacks
implant behaviour activated by a trigger \cite{gu2019badnets}. Model-extraction attacks
instead aim to reproduce a deployed model through access to its prediction interface
\cite{tramer2016stealing}. Chapter~\ref{chap:advml} evaluates evasion; the Android studies
report predictive performance on historical samples.

\paragraph{Feature space and problem space.} A feature-space attack modifies the representation
supplied to the learner. A problem-space attack modifies the underlying artefact.
Pierazzi et al.\ formalise constraints on the available transformations and preservation of
semantics, alongside plausibility and robustness to preprocessing \cite{pierazzi2020intriguing}.
For malware, the modified package must retain its malicious functionality as well as remain
valid. A successful feature-space perturbation need not correspond to such a package.
Android studies illustrate both feature-space attacks \cite{grosse2017adversarial} and
functionality-preserving changes to applications that affect their extracted call graphs
\cite{song2026fcghunter}.

\paragraph{Adaptive attacks and robustness.} An adaptive attack is designed against the
specific defended system, including its preprocessing and response policy
\cite{tramer2020adaptive}. Gradient masking can obstruct an attack's optimisation without
preventing adversarial errors \cite{athalye2018obfuscated}. Robustness claims therefore
require a stated threat model and budget, together with attacks appropriate to the complete
defence \cite{carlini2019evaluating}. FGSM and PGD provide reference gradient-based methods
\cite{goodfellow2015explaining,madry2018pgd}.

Reusable attack libraries such as Foolbox provide common model interfaces and attack criteria
\cite{rauber2017foolbox}; the NIPS~2017 competition evaluated attacks and defences submitted
by independent teams \cite{kurakin2018competition}. Such infrastructure supports empirical
evaluation. Its results still depend on input validity and scoring conventions, which
Section~\ref{sec:background:metrics:adversarial} defines for the present dissertation.

\section{Performance Measures and Evaluation Methodology}
\label{sec:background:evaluation}

This section defines the measures used in Chapters~\ref{chap:hybroid} to~\ref{chap:advml}, with
explicit observation units and aggregation rules. Dimensionless scores are proportions:
$m$ corresponds to $100m$ per cent, and $m_1-m_2$ to $100(m_1-m_2)$ percentage points.

\subsection{Observation Units and Confusion Counts}
\label{sec:background:metrics:counts}

Let $\mathcal D=\{(x_i,y_i)\}_{i=1}^{N}$ be a labelled evaluation set with $N>0$, and let
$\widehat y_i=h(x_i)$ be the prediction of a fitted classifier. For a single-label task with
class set $\mathcal Y$, the confusion matrix $\mathbf C$ records true labels in its rows and
predicted labels in its columns:
\begin{equation}
  C_{ab}=\sum_{i=1}^{N}\mathbf1\{y_i=a,\ \widehat y_i=b\},
  \qquad a,b\in\mathcal Y.
  \label{eq:background:confusion}
\end{equation}
In binary security detection, $1$ denotes the labelled attack or malware class and $0$ the
normal or benign class. With both axes
ordered as $(0,1)$,
\begin{equation}
  \mathbf C_{\mathrm{bin}}=
  \begin{pmatrix}\mathrm{TN}&\mathrm{FP}\\\mathrm{FN}&\mathrm{TP}\end{pmatrix},
  \qquad N=\mathrm{TP}+\mathrm{TN}+\mathrm{FP}+\mathrm{FN}.
  \label{eq:background:binary-confusion}
\end{equation}
True positives and true negatives are correct decisions. A false positive flags a negative
observation; a false negative misses a positive observation \cite{fawcett2006roc}.

Table~\ref{tab:background:tasks} maps the decision units and targets of the contribution chapters.
The input representation can have a different granularity: the SWaT model processes windows,
then assigns one prediction to each timestamp. Timestamp metrics give longer attacks more
weight; episode-level assessment requires a separate matching rule and denominator
\cite{sorbo2024navigating}. Collapsing attack types into one positive class turns errors
between those types into correct binary detections (Section~\ref{sec:anomaly:iuno-results}).

\subsection{Binary Detection Measures and Class Prevalence}
\label{sec:background:metrics:binary}

Accuracy $A$ is the fraction of all observations classified correctly. Precision $P$ is the
fraction of positive predictions that are correct, whereas recall $R$ is the fraction of
positive observations detected:
\begin{equation}
  A=\frac{\mathrm{TP}+\mathrm{TN}}{N},\qquad
  P=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},\qquad
  R=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}}.
  \label{eq:background:accuracy-precision-recall}
\end{equation}
Recall is also called sensitivity or the true-positive rate (TPR). The $F_1$ score combines
precision and recall through their harmonic mean:
\begin{equation}
  F_1=\frac{2\mathrm{TP}}{2\mathrm{TP}+\mathrm{FP}+\mathrm{FN}},\qquad
  H(P,R)=\frac{2PR}{P+R}=F_1
  \quad\text{when the ratios are defined}.
  \label{eq:background:f1}
\end{equation}
The count form omits true negatives and gives $F_1=0$ when $\mathrm{TP}=0$ and
$\mathrm{FP}+\mathrm{FN}>0$. We use the continuous extension $H(0,0)=0$ when both defined rates
are zero
\cite{fawcett2006roc,sorbo2024navigating}.

False-positive and false-negative rates (FPR and FNR) measure class-conditional errors.
Specificity, or true-negative rate (TNR), complements FPR; balanced accuracy averages the two class recalls
\cite{fawcett2006roc,grandini2020metrics}:
\begin{equation}
  \begin{aligned}
    \mathrm{FPR}&=\frac{\mathrm{FP}}{\mathrm{FP}+\mathrm{TN}},
    &\mathrm{TNR}&=\frac{\mathrm{TN}}{\mathrm{TN}+\mathrm{FP}}=1-\mathrm{FPR},\\
    \mathrm{FNR}&=\frac{\mathrm{FN}}{\mathrm{TP}+\mathrm{FN}}=1-R,
    &\mathrm{BAcc}&=\frac{R+\mathrm{TNR}}{2}.
  \end{aligned}
  \label{eq:background:error-rates}
\end{equation}
The false fraction among positive predictions is $1-P=\mathrm{FP}/(\mathrm{TP}+\mathrm{FP})$,
with a different denominator from FPR. Zero denominators make ratios undefined unless an
explicit replacement or exclusion rule is given.

Let $\pi=(\mathrm{TP}+\mathrm{FN})/N$ be the positive-class prevalence. Writing precision and
accuracy in terms of the class-conditional rates gives
\begin{equation}
  \begin{aligned}
    P(\pi)&=\frac{\pi\,\mathrm{TPR}}
      {\pi\,\mathrm{TPR}+(1-\pi)\,\mathrm{FPR}},\\
    A(\pi)&=\pi\,\mathrm{TPR}+(1-\pi)\,\mathrm{TNR}.
  \end{aligned}
  \label{eq:background:prevalence}
\end{equation}
Bayes' rule gives the precision identity \cite{axelsson2000base}. Varying $\pi$ at fixed TPR
and FPR gives a conditional prevalence-sensitivity calculation (Section~\ref{sec:hgann:10}).
Balanced accuracy removes the explicit prevalence weights, but changes in class-conditional
data distributions can still change both recalls.

\subsection{Multiclass and Multilabel Aggregation}
\label{sec:background:metrics:aggregation}

For $K$ mutually exclusive classes, treating class $k$ as positive and the remainder as
negative gives classwise measures $M_k$. Let $n_k$ denote the support of class $k$ and
$\pi_k=n_k/N$. Macro and support-weighted averages are
\begin{equation}
  M_{\mathrm{macro}}=\frac1K\sum_{k=1}^{K}M_k,
  \qquad
  M_{\mathrm{weighted}}=\sum_{k=1}^{K}\pi_k M_k.
  \label{eq:background:class-averages}
\end{equation}
Multiclass balanced accuracy is $R_{\mathrm{macro}}$. Macro $F_1$ gives each class equal
weight, whereas weighted $F_1$ reflects the class distribution. Chapter~\ref{chap:anomaly}
reports both because normal records dominate the S7-300 data.

Micro averaging pools the one-versus-rest counts. For a single-label task with one prediction
per observation and all classes included, it reduces to
\begin{equation}
  P_{\mathrm{micro}}=R_{\mathrm{micro}}=F_{1,\mathrm{micro}}
  =R_{\mathrm{weighted}}=A=\frac{\operatorname{tr}(\mathbf C)}{N}.
  \label{eq:background:micro-identity}
\end{equation}
This identity assumes defined class recalls or an explicit zero-fill rule
\cite{grandini2020metrics}. Here, macro $F_1$ means the average of the classwise $F_1$ scores,
which differs from the harmonic mean of macro precision and recall
\cite{opitz2019macrof1}. Reports must therefore state the class set and zero-denominator rule.

Multilabel prediction assigns several binary labels to each observation. In the facial-attribute
task, the reported accuracy averages the $J$ label decisions for each observation:
\begin{equation}
  A_{\mathrm{attr}}=\frac1{NJ}\sum_{i=1}^{N}\sum_{j=1}^{J}
    \mathbf1\{\widehat y_{ij}=y_{ij}\}.
  \label{eq:background:attribute-accuracy}
\end{equation}
Chapter~\ref{chap:advml} uses $J=40$; the score does not require every attribute of an image
to be correct \cite{sparta2022d76}.

\subsection{ROC Curves and Area under the Curve}
\label{sec:background:metrics:roc}

For scores $s_i$ whose larger values favour the positive class, thresholding gives
$\widehat y_i(\tau)=\mathbf1\{s_i\geq\tau\}$. Varying $\tau$ traces the receiver operating
characteristic (ROC) points $(\mathrm{FPR}(\tau),\mathrm{TPR}(\tau))$
\cite{fawcett2006roc}. With $r(u)$ the linearly interpolated TPR at FPR $u$, the empirical area
under the curve (AUC) is
\begin{equation}
  \begin{aligned}
    \mathrm{AUC}&=\int_0^1 r(u)\,\mathrm du\\
    &=\frac1{N_+N_-}\sum_{i:y_i=1}\sum_{j:y_j=0}
      \left[\mathbf1\{s_i>s_j\}+\frac12\mathbf1\{s_i=s_j\}\right],
  \end{aligned}
  \label{eq:background:auc}
\end{equation}
where $N_+,N_->0$ count positive and negative observations. AUC measures positive--negative pair ranking,
with half credit for ties. Perfect and independent random rankings give one and expected
$0.5$, respectively. One confusion matrix gives only an operating point; AUC specifies neither
a deployment threshold nor probability calibration.

Multiclass one-versus-rest curves compare each class with the remainder. Unweighted macro AUC
is $K^{-1}\sum_k\mathrm{AUC}_k$; other weighting or curve-averaging conventions must be stated
\cite{fawcett2006roc}. \hybroid{} reports per-class ROC AUC (Chapter~\ref{chap:hybroid}).

\subsection{Performance under Adversarial Input}
\label{sec:background:metrics:adversarial}

An adversarial performance measure requires a fixed threat model and valid perturbed inputs
\cite{carlini2019evaluating}. For an attack $a$ applied to matched, single-label observations,
let $A_{\mathrm{clean}}$ be the clean accuracy and define
\begin{equation}
  A_a=\frac1N\sum_{i=1}^{N}\mathbf1\{h(a(x_i))=y_i\},
  \qquad \Delta_a=A_{\mathrm{clean}}-A_a.
  \label{eq:background:accuracy-loss}
\end{equation}
The SAFAIR score in Chapter~\ref{chap:advml} uses this signed accuracy difference
\cite{sparta2022d76}. For the attribute task, Equation~\ref{eq:background:attribute-accuracy}
supplies both terms. Report clean and attacked accuracy alongside the loss: equal differences
can occur at different levels of classification performance.

Attack success measures attainment of a specified goal. One explicit convention restricts
evaluation to initially correct examples, $I_{\mathrm{corr}}=\{i:h(x_i)=y_i\}$. For target
labels $t_i$, let $I_t=\{i\in I_{\mathrm{corr}}:t_i\neq y_i\}$. Conditional untargeted and
targeted attack-success rates are then
\begin{equation}
  \begin{aligned}
    \mathrm{ASR}_{\mathrm{untargeted}}
      &=\frac1{|I_{\mathrm{corr}}|}\sum_{i\in I_{\mathrm{corr}}}
        \mathbf1\{h(a(x_i))\neq y_i\},\\
    \mathrm{ASR}_{\mathrm{targeted}}
      &=\frac1{|I_t|}\sum_{i\in I_t}\mathbf1\{h(a(x_i))=t_i\}.
  \end{aligned}
  \label{eq:background:attack-success}
\end{equation}
Report eligible-set sizes and any alternative eligibility rule; empty sets give undefined rates.
These goal-specific rates differ from $\Delta_a$. Chapter~\ref{chap:advml} develops attribute
criteria and per-example attack-suite aggregation as analytical measures, not recovered contest
scores. Finite attacks do not certify worst-case robustness
\cite{carlini2019evaluating}.

\subsection{Experimental Protocol and Bias}
\label{sec:background:evaluation:bias}

Malware evaluation should use training samples collected before the test period. The test set
should match the conditions expected during deployment \cite{pendlebury2019tesseract}.
Preprocessing and model selection must exclude test information; data-dependent transformations
are fitted within each training fold \cite{arp2022dos}. Repackaged applications require
checks for dependence across partitions \cite{irolla2018duplication}.

Baseline comparisons should use a common evaluation protocol on shared data partitions and
include simple alternatives \cite{arp2022dos}. Claims about individual components require
controlled ablations. Reports
must distinguish class averaging from averaging across folds or training runs. For nonlinear
measures such as $F_1$, the mean of individual scores can differ from the score calculated from
pooled counts. \hybroid{} uses five-fold cross-validation, while \hgann{} reports five-run means
on a fixed partition. The contribution chapters specify their protocols and the resulting
limits on interpretation.

\section{Summary and Research Gaps}
\label{sec:background:summary}

The observation model determines which evidence reaches a detector. Program graphs and
hypergraphs structure that evidence, while their learning operators determine how it is
combined. Network and process studies make corresponding choices at other observation
scales. Evaluation then relates the predictions to a defined population and, where relevant,
to permitted adversarial modifications. The following gaps connect these foundations to the
research questions in Section~\ref{sec:intro:rqs}.

\phantomsection
\paragraph{G1. Combining program structure with observed behaviour.}\label{gap:1}
MARVIN and the study by Onwuzurike et al.\ report benefits from combining static and dynamic
features in within-system comparisons \cite{lindorfer2015marvin, onwuzurike2018family}.
Those results concern particular observation types and prediction tasks. A different pair
first needs a joint representation at a common unit of analysis. Whether the benefit persists
then requires comparison of that representation with each modality alone on the same samples.
RQ1 addresses both steps for program structure and network behaviour in binary detection and
malware-category classification.

\phantomsection
\paragraph{G2. The empirical value of higher-order program representations.}\label{gap:2}
Prior Android work uses call-neighbour and permission-based hyperedges for application
classification \cite{zhang2023android}. It remains open how program groups should be
constructed and weighted for malware analysis, and how much such representations add over
pairwise graphs under a common protocol. Attributing a gain to construction or to
weighting would further require varying them separately. RQ2 addresses this question for
binary detection and dataset-specific malware classification.

\phantomsection
\paragraph{G3. Representations for modular industrial anomaly detection.}\label{gap:3}
Communication whitelists and host-pair models use relations observed between devices
\cite{barbosa2013flow,yoon2014communication}, while process detectors use sensor and actuator
measurements \cite{goh2016swatdataset}. These observation types require different feature
preparation and decision units. The design question is how a modular learning framework can
accommodate both forms without tying the surrounding pipeline to one estimator. RQ3 examines
this question through \nadics{} and its separate network and process evaluations.

\phantomsection
\paragraph{G4. Reproducible and interpretable adversarial evaluation.}\label{gap:4}
Attack libraries and public competitions provide established evaluation infrastructure
\cite{rauber2017foolbox,kurakin2018competition}. Reuse across prediction tasks still requires
explicit attacker access and valid perturbation constraints. Scoring must match the prediction
objective, and attacks must address the complete defended system
\cite{carlini2019evaluating}. The question is how these requirements can be implemented in
reusable protocols and which conclusions joint clean and attacked measurements support.
RQ4 addresses this benchmark-design and measurement problem.
