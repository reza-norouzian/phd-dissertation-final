Chapters~\ref{chap:anomaly} to~\ref{chap:advml} contribute methods for representing
security-relevant context and procedures for evaluating learning-based decisions. This
discussion relates their design choices to the evidence each study provides. The comparison
between \hybroid{} and \hgann{} is conceptual; empirical comparisons remain within the
corpus and protocol of each study.

\section{Contributions of Contextual Representations}
\label{sec:discussion:representations}
\label{sec:discussion:1}
\label{sec:discussion:2}

The IoT service-graph design makes communication partners part of the detection decision.
Each node stores observed relations as its reference and permits an operator to approve
new legitimate interactions \cite{aubet2018graph}. In the industrial work, \nadics{}
represents network connections through protocol features, while the SWaT detector analyses
process measurements in multivariate time windows. Chapter~\ref{chap:anomaly} thus
connects representation design to the unit of observation available in each setting.

\hybroid{} studies context across evidence sources. Its static graph describes program
structure, and its flow features summarise network behaviour observed during execution
\cite{norouzian2021hybroid}. The within-system comparison in
Table~\ref{tab:hybroid:fusion-effects} reports higher detection $F_1$ for fusion than for
either branch alone. For category classification, fusion improved the ensemble results,
while the decision tree favoured static features. The contribution includes a direct
measurement of the value of combining these observations for the tested tasks and learners.

\hgann{} studies context within the application package. It groups methods by call
neighbourhood and semantic similarity; slice-aware hyperedges add relations around
security-sensitive call sites \cite{norouzian2025hgannmal}. These groups define which
methods contribute together to a hyperedge representation. The hypergraph configurations
achieved higher reported accuracy than the pairwise baselines for binary detection and for
the dataset-specific classification tasks: families on Drebin and categories on CICMalDroid
(Tables~\ref{tab:hgann:binary} and~\ref{tab:hgann:multi}). These are comparisons of complete
configurations. Comparisons with non-attentive operators vary both construction and
weighting; an attention-only effect requires a controlled ablation.

The operator analysis in Section~\ref{sec:hgann:8} gives a separate account of what learned
weighting can represent. Different hyperedge groupings can produce different attentive
propagation even when they produce the same fixed propagation matrix. This capacity depends
on the grouping retained during construction: attention adjusts existing memberships. The
distinction connects the model's mathematical properties to the program relations made
available by static analysis.

The SWaT comparison adds an operating-objective perspective. Full process inputs gave the
highest reported recall, while the PCA configurations reduced the false-positive rate
(Table~\ref{tab:anomaly:gan-representations}). The preferred configuration therefore depends
on the relative importance of detecting anomalous observations and reducing false-positive
observations. Across these studies, the useful question is which context serves the
prediction task, with the comparison made under a stated protocol.

\section{Observation Requirements and Analysis Cost}
\label{sec:discussion:observation}
\label{sec:discussion:3}
\label{sec:discussion:5}

Static and multimodal analysis place different requirements on data acquisition.
\hybroid{}'s evaluation reused traffic supplied by CICAndMal2017 alongside each application
package. Its fused representation therefore requires a recorded execution. \hgann{}
constructs its representation from the package, so it can be applied without arranging a
runtime capture. This separates the effort of obtaining an additional observation from the
computational work of modelling static structure.

Chapter~\ref{chap:hgann} also provides a computational account of higher-order
representation. The hyperedge cardinality cap bounds retained memberships, and the sparse
representation grows linearly with the numbers of methods and slices
(Equation~\ref{eq:hgann:sizes}). Construction adds call-graph searches and comparisons
between semantic embeddings. The bounds in Section~\ref{sec:hgann:13} distinguish this
stage from propagation and make their scaling assumptions explicit. An end-to-end runtime
comparison would require measurements under common hardware and workloads.

Observation requirements also define the evaluation cohort. \hybroid{} compares modalities
on the same applications with both representations available, which permits a matched
comparison on that cohort. CICMalDroid supplies applications retained by its authors'
dynamic-analysis procedure \cite{mahdavifar2020dynamic}; \hgann{} then extracts static
representations from these packages. The processing requirements of a detector and the
acquisition history of its benchmark are therefore separate properties. Recording both
makes explicit which applications and operating conditions a reported result describes.

\section{Evaluation Principles Across the Contributions}
\label{sec:discussion:evaluation}
\label{sec:discussion:4}
\label{sec:discussion:6}

Representation design determines the evidence available to a detector. Predictive evaluation
measures how effectively it uses that evidence, while adversarial evaluation examines its
decisions when an attacker deliberately modifies the input. The SAFAIR contest and benchmark
in Chapter~\ref{chap:advml} contribute a procedure for investigating this second question
under explicit attacker assumptions.

Reusable software provides a second connection between the contribution chapters.
\nadics{} places estimators behind a common interface, so that researchers can change
learning methods without rewriting the surrounding pipeline \cite{iuno_ap4}.
SAFAIR applies a corresponding separation to evaluation: attack implementations share an
execution procedure, while task-specific components define the model and data interfaces
\cite{sparta2022d76}. Vicomtech's application of the framework to histopathology defences
demonstrates reuse on a prediction task outside the facial-image contest
\cite[Section~3.1.3.1]{sparta2022d76}. Both frameworks separate components that researchers
can vary within one configured procedure.

The Android studies provide within-system comparisons under their own protocols. \hybroid{} holds
the applications and learner fixed when comparing input modalities. The \hgann{}
evaluation supplies common call graphs and node features to its relational configurations.
Matching inputs and protocols makes these contrasts interpretable; their reported margins
remain point estimates. Time-ordered evaluation addresses the additional question of
performance on later observations \cite{pendlebury2019tesseract}. Each comparison can thus
be read against the conditions it was designed to examine.

Chapter~\ref{chap:advml} adds analytical criteria for interpreting evaluation scores. A
constant predictor has zero accuracy loss under label-preserving attacks
(Equation~\ref{eq:advml:constant}), even when its classification utility is limited.
Clean and attacked accuracy therefore answer different questions and should be reported
together. Under the benchmark's binary label-reversal response,
Equation~\ref{eq:advml:reversal-gain} relates the change in task accuracy to the correct and
incorrect base predictions that trigger an alarm. These derivations make the scoring
procedure part of the scientific contribution. Their assumptions can be examined independently of a particular benchmark,
and they specify outcomes needed to assess the complete defended system
\cite{carlini2019evaluating}.

\section{Implications for Android Malware Analysis}
\label{sec:discussion:implications}
\label{sec:discussion:7}

For Android analysis, the distinction between acquiring evidence and structuring it gives
two design choices that can be investigated together. A common-cohort evaluation could
compare static relational encodings and then measure the additional value of traffic for
the same prediction task. Acquisition effort and construction time would give those
performance differences an operational interpretation.

The SAFAIR evaluation design provides a basis for extending such a comparison to an
explicit adversary. Android-specific tests would use valid package transformations that
preserve malicious functionality and would assess the complete pipeline, including fusion
where applicable \cite{carlini2019evaluating}. The Android studies establish predictive
results; resistance to those transformations remains a question for that evaluation.
Together, the contributions relate contextual modelling to the evidence and measurement
procedures needed to assess a security-analysis system.
